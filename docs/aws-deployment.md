# AWS deployment runbook

This runbook deploys the `PulseApiMonitorDev` stack to `us-west-2`. It assumes the AWS CLI is configured for a non-root IAM user.

## 1. Safety checks

Confirm the active identity and region:

```bash
aws sts get-caller-identity --query Arn --output text
aws configure get region
```

Stop if the ARN ends in `:root` or the region is not `us-west-2`.

Do not store access keys, secret keys, downloaded credential CSV files, or passwords in this repository. The included `.gitignore` blocks common credential filenames, but it is not a substitute for careful handling.

## 2. Local validation

```bash
npm test
npm --prefix infra install
npm --prefix infra test
npm run infra:build
npm run infra:synth
```

Expected test scope:

- Assertion evaluation and JSON path handling
- Private-network target blocking
- Failure threshold and recovery transitions
- CloudFormation resource counts and serverless architecture properties
- Conditional $5 monthly forecast budget

## 3. Bootstrap CDK

CDK bootstrap creates deployment support resources in the AWS account and region. This only needs to happen once per account/region combination.

```bash
cd infra
npx cdk bootstrap
```

## 4. Review the change set

```bash
npx cdk diff
```

The initial stack should contain:

- 6 DynamoDB tables and 2 global secondary indexes
- 1 FIFO work queue, 1 FIFO worker dead-letter queue, and 1 standard Scheduler dead-letter queue
- 3 ARM64 Node.js Lambda functions
- 1 EventBridge Scheduler schedule
- 1 API Gateway HTTP API
- 1 Cognito user pool and public web client
- 1 SNS topic
- 1 private S3 web-assets bucket and 1 CloudFront distribution
- 3 CloudWatch alarms
- Least-resource-scoped Lambda and scheduler IAM roles generated by CDK

Worker concurrency is intentionally governed by the FIFO queue rather than Lambda reserved concurrency so the stack works with the lower concurrency quota commonly assigned to new AWS accounts.

Application roles are scoped to their exact tables, queues, topic, function, or API routes. CDK's temporary web-deployment provider has its generated permissions, including CloudFront invalidation access. Development data, queues, and web assets use delete-on-destroy policies; deleting the stack deletes their contents.

## 5. Deploy

To deploy without email subscriptions or an AWS Budget resource:

```bash
npx cdk deploy --require-approval broadening
```

After deployment, verify the complete authenticated check path with a temporary synthetic account:

```bash
../scripts/aws-smoke-test.sh
```

The smoke test verifies persisted aggregates, alert-account isolation, maintenance suppression, and the public status page, then removes its Cognito user, monitor, checks, incidents, aggregates, and page before exiting. It requires `aws`, `curl`, `jq`, and `openssl`.

To deploy with a $5 monthly forecast budget and SNS email subscription, substitute an email address you control:

```bash
npx cdk deploy -c budgetEmail=you@example.com --require-approval broadening
```

The command prints the API URL, Cognito user pool ID, web client ID, and SNS topic ARN. Each user configures an email under Account & security and must confirm AWS's subscription email before expecting incident alerts.

## 6. Smoke test

The health endpoint does not require authentication:

```bash
curl "$(aws cloudformation describe-stacks --stack-name PulseApiMonitorDev --query 'Stacks[0].Outputs[?OutputKey==`ApiUrl`].OutputValue' --output text)/health"
```

Expected response:

```json
{"status":"ok","service":"pulse-api","timestamp":"..."}
```

Protected monitor routes require a Cognito JWT and are intentionally unavailable anonymously.

## 7. Cleanup

```bash
npx cdk destroy
```

Review the CloudFormation console afterward to confirm the stack is gone. The Cognito user pool, monitor history, incidents, checks, queues, and log groups are development resources and are deleted with the stack.
